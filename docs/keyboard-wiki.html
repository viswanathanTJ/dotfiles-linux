Physical keyboard

Your keys

Toshy maps keys by position, like a real Mac keyboard (Control · Option · Command · space). On this PC keyboard the bottom-left row is Ctrl · Win · Alt · space:

Caps LockCtrl / EscHold = real Ctrl. Double tap = Esc (one tap does nothing). Both Shifts = real Caps Lock.
Left CtrlControlMac Control: real Ctrl in terminals, Mac-style in apps.
WinOptionWord jumps. Win+1…9 = dock apps (like Windows). Tapping it does nothing.
Left AltCmd ⌘Copy, paste, tabs, quit, app switching.
SpaceAlt+Space opens Activities (Launchpad), like Cmd+Space.

Toshy's internal names in its config: RC = Cmd (it turns Alt into Right Ctrl), LC = a real Ctrl (Caps held), Super = Mac Control (Left Ctrl in apps), Alt = Option (Win).

Mechanism

How a key press travels

Three layers turn a physical key press into an action. Each layer only sees what the one before it sends.

1 · Keyboard
Physical keys
Alt + Caps + B
2 · Toshy
Remaps by position and app
Alt→Cmd (RC), Caps held→Ctrl (LC). Rule RC-LC-b sends Ctrl+Alt+B
3 · GNOME
Settings & shortcuts
xkb options, Alt+Tab, overview, custom shortcuts
4 · Extension / app
Acts on the result
Run or Raise sees Ctrl+Alt+B: focus Chrome or launch it

Toshy (keymapper)

A background service (toshy-config.service) that grabs the keyboard and re-sends keys through a virtual keyboard (XWayKeyz). It knows the focused app through the Focused Window D-Bus extension, so terminals and apps get different rules. Its config is Python; your edits live between SLICE_MARK lines so upgrades keep them.

GNOME settings

Stored in dconf, changed with gsettings. They apply instantly. GNOME sees keys after Toshy, so a GNOME keyboard option (like ctrl:nocaps) is invisible to Toshy's rules.

Run or Raise (extension)

On Wayland, apps can't focus other apps' windows. A GNOME Shell extension runs inside GNOME and can. It listens for Ctrl+Alt+letter and focuses or launches the matching app from shortcuts.conf.

GNOME custom shortcuts

Run a command for a key: CopyQ (copyq show) and Screen OCR (~/.local/bin/screen-ocr). Toshy sends their keys when you press the Mac-style combination.

Step by step

Rebuild on a new machine

Order matters. Commands are for fish. Every file is in Exact configs.

  1. Allow user extensions. A master switch can silently disable every extension you install.
    fish
    gsettings set org.gnome.shell disable-user-extensions false
  2. Install the two GNOME extensions (GNOME 46 versions), then log out and back in: Wayland loads new extensions only at login.
    fish
    curl -fL -o /tmp/focused-window-dbus.zip "https://extensions.gnome.org/download-extension/focused-window-dbus@flexagoon.com.shell-extension.zip?version_tag=62865"
gnome-extensions install --force /tmp/focused-window-dbus.zip
curl -fL -o /tmp/run-or-raise.zip "https://extensions.gnome.org/download-extension/run-or-raise@edvard.cz.shell-extension.zip?version_tag=75680"
gnome-extensions install --force /tmp/run-or-raise.zip
# create ~/.config/run-or-raise/shortcuts.conf BEFORE enabling (see Exact configs),
# otherwise Run or Raise copies in its own example shortcuts
# log out, log in, then:
gnome-extensions enable focused-window-dbus@flexagoon.com
gnome-extensions enable run-or-raise@edvard.cz
    For a different GNOME version, look up the download with https://extensions.gnome.org/extension-info/?pk=5592&shell_version=NN (Focused Window D-Bus) and pk=1336 (Run or Raise).
  3. Install Toshy as your normal user (it asks for the sudo password itself), then log out and back in.
    fish
    curl -fL -o /tmp/toshy.zip https://github.com/RedBearAK/toshy/archive/refs/heads/main.zip
unzip -o /tmp/toshy.zip -d ~/Downloads/
cd ~/Downloads/Toshy-main; ./setup_toshy.py install
  4. Set Toshy's preferences: tray icon → Preferences, or toshy-gui. CapsLock Mode "Caps is Esc & LCtrl always"; Super Tap Passthru both off. Or set them directly:
    fish
    python3 -c 'import sqlite3,os
c=sqlite3.connect(os.path.expanduser("~/.config/toshy/toshy_user_preferences.sqlite"))
for k,v in [("capslock_mode","caps_is_caps"),("l_cmd_is_sup_and_cmd","False"),("l_opt_is_sup_and_opt","False")]:
    c.execute("update config_preferences set value=? where name=?",(v,k))
c.commit()'
  5. Add the custom Toshy rules: paste the user_apps block into ~/.config/toshy/toshy_config.py, replacing the existing user_apps section between its SLICE_MARK lines.
  6. Apply the GNOME settings: run the GNOME settings script.
  7. Install the helpers: CopyQ (sudo apt install copyq, then the autostart line), Screen OCR (sudo apt install tesseract-ocr tesseract-ocr-eng wl-clipboard libnotify-bin, then the script), and the reload-shortcuts fish function.
  8. Reload and test: run reload-shortcuts, then go through the cheatsheet. If anything freezes: toshy-services-stop.

# Caps: hold = real Ctrl, single tap = nothing, quick double tap = Esc.
# Needs Toshy's CapsLock mode "caps_is_caps" (Toshy leaves the key alone, so this is the only Caps rule).
# Tap sends F16, an unused key that the keymap below always swallows; real Caps Lock = both Shift keys.
multipurpose_modmap("User Caps tap F16 / hold Ctrl", {
    Key.CAPSLOCK:               [Key.F16, Key.LEFT_CTRL]
}, when = lambda ctx:
    cnfg.screen_has_focus and
    not ctx_app_is_remote
)

# Double-tap window for isDoubleTap (Toshy's default 0.24 s, doubled). Set here, inside the
# user_apps section, so it survives Toshy upgrades.
tapInterval = 0.48

keymap("User Caps double tap", {
    # isDoubleTap sends Esc the moment the 2nd tap lands (MultiTap waited another 0.25 s
    # for a possible 3rd tap). Taps must be within tapInterval (above); a single tap does nothing.
    C("F16"): isDoubleTap(C("Esc")),
}, when = lambda ctx:
    cnfg.screen_has_focus and
    not ctx_app_is_remote
)

GNOME settings script

  
Every keyboard-related GNOME change on this machine, as commands. Safe to re-run.

  
fish
# Keyboard options: Caps = Ctrl (when Toshy is off), both Shift keys = Caps Lock
gsettings set org.gnome.desktop.input-sources xkb-options "['ctrl:nocaps', 'shift:both_capslock']"
# Win tap does nothing (Toshy default); Activities on Shift+Ctrl+Space = Alt+Space via Toshy
gsettings set org.gnome.mutter overlay-key ''
gsettings set org.gnome.shell.keybindings toggle-overview "['<Shift><Control>space']"
# Alt+Tab switches apps, not windows
gsettings set org.gnome.desktop.wm.keybindings switch-applications "['<Super>Tab', '<Alt>Tab']"

Screen OCR · ~/.local/bin/screen-ocr (executable)

  
Opens GNOME's screenshot tool through the xdg-desktop-portal, runs Tesseract on the selection, copies the text with wl-copy and shows a notification. Make it executable with chmod +x ~/.local/bin/screen-ocr.

  
python
#!/usr/bin/python3 -I
"""Select a screen area, OCR it with Tesseract and copy the text (works on GNOME Wayland).

Uses the xdg-desktop-portal Screenshot API, which opens GNOME's own screenshot
tool, so it works where X11 screen grabbing (dpScreenOCR) does not.
Language: OCR_LANG env var, default "eng" (e.g. OCR_LANG=eng+tam).
"""
import os
import subprocess
import urllib.parse

import gi

gi.require_version("Gio", "2.0")
from gi.repository import Gio, GLib

LANG = os.environ.get("OCR_LANG", "eng")
PORTAL = "org.freedesktop.portal.Desktop"


def notify(title, body=""):
    subprocess.run(["notify-send", "-a", "Screen OCR", "-i", "edit-copy", title, body[:200]])


bus = Gio.bus_get_sync(Gio.BusType.SESSION)
loop = GLib.MainLoop()
result = {}
token = f"screenocr{os.getpid()}"
sender = bus.get_unique_name()[1:].replace(".", "_")
request_path = f"/org/freedesktop/portal/desktop/request/{sender}/{token}"


def on_response(conn, snd, path, iface, signal, params):
    code, results = params.unpack()
    result["code"] = code
    result["uri"] = results.get("uri")
    loop.quit()


bus.signal_subscribe(PORTAL, "org.freedesktop.portal.Request", "Response", request_path,
                     None, Gio.DBusSignalFlags.NONE, on_response)
bus.call_sync(PORTAL, "/org/freedesktop/portal/desktop", "org.freedesktop.portal.Screenshot",
              "Screenshot",
              GLib.Variant("(sa{sv})", ("", {"handle_token": GLib.Variant("s", token),
                                             "interactive": GLib.Variant("b", True)})),
              None, Gio.DBusCallFlags.NONE, -1, None)
GLib.timeout_add_seconds(120, loop.quit)
loop.run()

if result.get("code") != 0 or not result.get("uri"):
    raise SystemExit(0)  # cancelled

image = urllib.parse.unquote(urllib.parse.urlparse(result["uri"]).path)
try:
    ocr = subprocess.run(["tesseract", image, "-", "-l", LANG],
                         capture_output=True, text=True)
finally:
    os.remove(image)  # the portal saves a copy in ~/Pictures/Screenshots

text = ocr.stdout.strip()
if not text:
    notify("No text found", ocr.stderr.strip())
    raise SystemExit(1)

subprocess.run(["wl-copy"], input=text, text=True)
notify("Text copied", text)


  
reload-shortcuts · ~/.config/fish/functions/reload-shortcuts.fish

  
Run after editing the Toshy or Run or Raise config. It checks the Toshy config for typos first, so a mistake can't leave the keyboard unmapped.

  
fish
function reload-shortcuts --description 'Reload Run or Raise and Toshy after editing their configs'
    # Check the Toshy config first: a typo would stop Toshy and leave the keyboard unmapped
    set -l cfg ~/.config/toshy/toshy_config.py
    if not ~/.config/toshy/.venv/bin/python -I -m py_compile $cfg
        echo "Toshy config has an error (see above); nothing reloaded."
        return 1
    end
    rm -f ~/.config/toshy/__pycache__/toshy_config.*.pyc

    # Every Ctrl+Alt+<letter> in Run or Raise needs a Toshy rule RC-LC-<letter> (Alt+Caps+<letter>),
    # otherwise Toshy sends Alt+Caps+<letter> as Ctrl+<letter> and Run or Raise never sees it
    for key in (string match -rg '^<Control><Alt>([a-z0-9])' < ~/.config/run-or-raise/shortcuts.conf)
        if not string match -q "*C(\"RC-LC-$key\")*" < $cfg
            echo "Warning: Run or Raise has Ctrl+Alt+$key but Toshy has no rule for Alt+Caps+$key."
            echo "  Add to keymap \"User app launchers\" in $cfg:"
            echo "    C(\"RC-LC-$key\"):            C(\"C-Alt-$key\"),"
            echo "    C(\"RC-Super-$key\"):         C(\"C-Alt-$key\"),"
        end
    end

    # Run or Raise reads ~/.config/run-or-raise/shortcuts.conf only when it starts
    gnome-extensions disable run-or-raise@edvard.cz
    sleep 1
    gnome-extensions enable run-or-raise@edvard.cz
    # never leave it switched off (Alt+Caps+letter would stop opening apps)
    if not gnome-extensions info run-or-raise@edvard.cz | string match -q '*Enabled: Yes*'
        sleep 1
        gnome-extensions enable run-or-raise@edvard.cz
    end
    if not gnome-extensions info run-or-raise@edvard.cz | string match -q '*Enabled: Yes*'
        echo "Run or Raise is still off. Run: gnome-extensions enable run-or-raise@edvard.cz"
        return 1
    end

    toshy-services-restart >/dev/null 2>&1
    sleep 5
    if systemctl --user is-active --quiet toshy-config
        echo "Shortcuts reloaded (Run or Raise + Toshy)."
    else
        echo "Toshy did not start. Check: toshy-services-status"
        return 1
    end
end

Lessons

Decisions & pitfalls

ChoiceWhy
Caps → Ctrl done inside ToshyToshy reads keys before GNOME's options. With only GNOME's ctrl:nocaps, Toshy doesn't know Caps is Ctrl, so Alt+Caps+B wouldn't match. ctrl:nocaps is still set so Caps is Ctrl when Toshy is stopped; with Toshy running it has no effect.
Toshy's built-in Caps mode, not custom Caps rulesHand-written Caps modmaps broke Enter, Backspace and Caps Lock. The built-in "Esc & LCtrl always" mode works.
Caps+Tab in terminals: own rule with bindToshy's built-in terminal rule C("LC-Tab"): C("C-PAGE_DOWN") has no bind (with the Caps tap/hold key it left Ctrl stuck in kitty), and kitty doesn't use Ctrl+PageDown for tabs. The user rule sends kitty's Ctrl+Tab / Ctrl+Shift+Tab with [bind, …].
Caps+W erases a word in appsCaps sends a real Linux Ctrl, so Caps+W was Ctrl+W = close tab. On a Mac, Ctrl+W never closes (Cmd+W does). The rule sends Ctrl+Backspace instead. Chrome is the exception: "User Chrome Caps" (checked first) keeps Caps+W = close tab and Caps+L = address bar.
Win+Backspace didn't delete a word in Teams for LinuxToshy sends a short Alt tap before Ctrl+Backspace; Electron apps with a hidden menu bar move focus to that menu on an Alt tap. Fixed with "menubar": "hidden" in ~/.config/teams-for-linux/config.json.
VS Code files.watcherExcludeVS Code watched every folder of ~/WorkSpace/ (61,800, 96% in node_modules) and used up the 65,536 inotify limit. Toshy then failed to start (inotify watch limit reached; found with xwaykeyz --check -c toshy_config.py). Plain folder patterns like **/node_modules cut it to about 2,000. The limit is also raised to 524,288 in /etc/sysctl.d/60-inotify-watches.conf (needs sudo; sudo sysctl --system applies it).
Caps+H/J/K/L = arrows in apps onlyIn terminals, Ctrl+H/J/K/L are backspace, newline, kill-line and clear, and your Neovim window moves, so the rule skips terminals. In apps the Ctrl+H/J/K/L shortcuts stay reachable with Alt (Cmd). Replaced the earlier Caps+J = Join Lines rule (now Left Ctrl+J). Snapshot before the change: milestone before-vim-arrows.
Avoid "Caps is LCtrl role swap"It turns Left Ctrl into Caps Lock; the Caps key then can't turn Caps Lock off.
Win tap does not open ActivitiesToshy sends Left Ctrl as Super. When it remaps a Left Ctrl combo, GNOME sees Super pressed and released and opens Activities by mistake. So overlay-key = '' (Toshy's default) and Activities is on Alt+Space.
No "tap Alt" for ActivitiesToshy's "L_Cmd is Super & Cmd" passthru together with the Caps tap/hold mode froze the keyboard. Keep both Super Tap Passthru options off.
CopyQ moved off Ctrl+Shift+VIn terminals Toshy turns Cmd+V into Ctrl+Shift+V (terminal paste), which the old CopyQ shortcut caught.
GNOME's Ctrl+Alt+T terminal shortcut offOtherwise Alt+Caps+T opens a new terminal as well as focusing kitty.
Run or Raise instead of GNOME custom shortcuts or the dockA GNOME custom shortcut can only launch. The dock's Super+N follows dock order. Run or Raise focuses or launches by window class.
Exact window-class regex for Chrome/^[Gg]oogle-chrome$/ skips Chrome web apps (Outlook, Teams), which have their own classes.
Stuck keys after a crash. If Toshy freezes and is stopped mid-press, GNOME can keep a key (often Super) "held". Symptoms: tapping Alt opens Activities, Alt+T does nothing. Fix: press and release Win, Ctrl, Alt and Shift once each; if that doesn't help, log out and back in.
Don't press shortcuts while reload-shortcuts runs. A key pressed while Toshy restarts can get stuck, and once the session ended mid-reload, which left Run or Raise disabled (Alt+Caps+letter stopped opening apps). Fix: gnome-extensions enable run-or-raise@edvard.cz.
When a logout is needed. After installing a new GNOME extension, and after a freeze. Not after Toshy rule changes, Toshy preferences or gsettings changes: those apply immediately (Toshy after reload-shortcuts or toshy-services-restart).
